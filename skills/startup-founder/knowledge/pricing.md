# Pricing

Pick a pricing model, design the tiers, and check the unit economics. Competitor prices anchor
everything here, so pull current pricing pages when the runtime has web access and label
remembered prices as possibly stale.

Input needed: the product, target market, and the founder's current pricing thinking (to confirm
or challenge). If their current idea is wrong, say so directly with the reason.

## 1. Model selection

Score each model 1-5 for fit with this product, with pros and cons:

| Model              | Fit | Pros | Cons |
|--------------------|-----|------|------|
| Flat subscription  |     |      |      |
| Usage-based        |     |      |      |
| Per-seat           |     |      |      |
| Freemium           |     |      |      |
| Credits / tokens   |     |      |      |
| One-time purchase  |     |      |      |

Recommend one model with the rationale.

## 2. Tier design

Design 3 tiers with names, monthly and annual prices (state the annual discount percentage), and
5-8 concrete features per tier with limits ("10 projects", never "advanced analytics"):

- Free or starter: what hooks users, and what triggers the upgrade.
- Pro or growth: what justifies the price jump; which "aha" feature is gated here.
- Business or scale: what unlocks here, and whether it is self-serve or sales-led.

Name each tier's upgrade trigger: the moment a customer outgrows it.

## 3. Competitive anchors

Reference 3-5 competitors' actual pricing and what it includes, and state where this product
should sit relative to each (above, below, between) and why.

## 4. Unit economics check

Rough numbers, assumptions stated: cost of goods per user per month (hosting, API costs,
support), gross margin per tier, break-even customer count per tier, and target blended ARPU.

## 5. Pricing psychology

Three tactics, applied concretely to the tiers just designed: which tier anchors the page,
whether a decoy tier pushes buyers toward the target tier, and how the annual discount is framed.

## 6. Launch pricing vs. scale pricing

What to charge in the first 90 days and why it differs from steady state, the grandfathering
policy for early adopters when prices rise, and the specific triggers for a price increase
("when feature X ships and retention holds", never "when we have more features").
