# Idea validation

Stress-test a startup idea before any code gets written. The output is a verdict, not a pep talk.

Input needed: the idea. Useful extras: who the founder is, what they can build, what they have
already tried.

## 1. The 30-second assessment

Open with your gut reaction in 2-3 sentences. Is this a real problem worth solving, or a solution
looking for a problem? Be direct; the rest of the analysis either backs this up or overturns it.

## 2. The five fatal questions

Answer each one honestly:

**Q1: Who is the customer, and would they pay for this today?**
Name the specific person (job title, company stage, situation) and estimate their willingness to
pay with a justification. If the answer is "maybe", treat it as a no.

**Q2: Why hasn't someone built this already?**
Someone has almost always tried. Name who, whether they failed or succeeded, and why. Then answer
what changed that makes now different: timing, technology, regulation, or a behavior shift.

**Q3: What is the distribution advantage?**
How do the first 100 users find this product? Is there a built-in growth loop, or is every user
acquired through paid or manual effort? "Content marketing and SEO" as the only answer is a red
flag at this stage.

**Q4: Can this be a big business, or is it a feature?**
Would an incumbent add this as a feature in a quarter? What is the natural ceiling in revenue and
users? What would need to be true for this to reach $1M ARR?

**Q5: Can this founder actually build it?**
What skills and resources does it require, what is the hardest technical or operational problem,
and is there a "first hire" dependency (cannot launch without a specific kind of expert)?

## 3. Scorecard

Rate each dimension 1-5:

| Dimension          | Score | Notes                                        |
|--------------------|-------|----------------------------------------------|
| Problem severity   |       | How painful is this today?                   |
| Market size        |       | How many people have the problem?            |
| Willingness to pay |       | Will they pay enough to build a business?    |
| Competition gap    |       | Is there real space for a new entrant?       |
| Distribution       |       | Can you reach customers cheaply?             |
| Timing             |       | Is this the right moment?                    |
| Founder fit        |       | Does the founder have an unfair advantage?   |
| **Total**          | /35   |                                              |

Scoring guide: 28-35 strong, validate fast and build; 21-27 promising with gaps, fix the weakest
dimension before building; 14-20 needs a major pivot or a different angle; below 14, start over.
The guide is a heuristic to force a ranking, not a formula.

## 4. Validation experiments

Recommend 3 experiments to run before writing code. Each one names a single assumption to test,
the exact steps (never "talk to users" without a script and a target count), a numeric success
criterion, and its time and cost. Every experiment fits in under 2 weeks and under $200. When an
experiment involves interviews, build the script per `user-interviews.md`.

## 5. The verdict

End with exactly one of:

- **Build it**, with the single most important thing to do this week.
- **Pivot it**, with the specific angle that would make the idea stronger and why.
- **Kill it**, with the reason, and name the adjacent problem that is actually worth solving.

## Rules

- Every critique names the fix; a hole without a next step is just discouragement.
- Cite real companies that succeeded or failed in the same space when you know them; when you are
  not sure a company or outcome is real, leave it out.
